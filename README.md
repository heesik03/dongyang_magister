# Magister

**작품의 설정과 원고를 비교하고, 작가의 판단을 다음 검토에 반영하는 AI 창작 검토 서비스**입니다.

## 프로젝트 소개

장기 연재에서는 인물의 능력이나 성격, 세계관 규칙, 이전 회차의 사건을 모두 기억하며 새 원고를 검토하기 어렵습니다. Magister는 한국어 소설·웹소설 작가가 작품별 설정과 회차 원고를 관리하고, 공개 전에 설정 충돌과 설명이 부족한 전개를 확인할 수 있도록 돕는 프로젝트입니다.

작가가 확정한 설정과 선택한 이전 원고를 검토 기준으로 삼습니다. AI가 충돌 가능성을 발견하면 문제 문장과 관련 설정·원고의 위치, 판단 이유와 수정 방향을 함께 보여줍니다. 단순한 문장 교정을 넘어 작품 고유의 맥락을 확인하는 데 초점을 둡니다.

핵심은 **작가의 판단이 쌓이는 검토 흐름**입니다. 작가는 결과를 수용하거나 보류하고, 반전이나 능력 변화처럼 의도한 전개는 ‘의도된 설정’으로 기록할 수 있습니다. 저장된 판단과 적용 사유는 다음 회차 분석의 참고 정보가 됩니다. 이때 특정 장면의 예외를 모든 상황에 적용하거나, 비슷한 충돌을 무조건 무시하지 않도록 합니다.


## 핵심 기능과 범위

아래는 개발 목표이며, 현재 구현 상태는 별도로 표시합니다. 첫 MVP는 한국어 텍스트와 작품별 설정 분석에 집중합니다.

| 기능 | 제공할 경험 | 우선순위 |
| --- | --- | --- |
| 작품·설정집 관리 | 작품별 인물·능력·세계관 규칙을 등록하고 확정 설정과 아이디어 구분 | P0 |
| 회차별 원고 관리 | 원고를 입력·수정하고 분석에 참고할 이전 회차 선택 | P0 |
| 설정 충돌 분석 | 새 원고와 확정 설정·이전 원고의 충돌 후보 및 문제 위치 확인 | P0 |
| 인물 개연성 검토 | 성격·목표와 행동·대사를 비교해 설명 보완이 필요한 부분 확인 | P0 |
| 검토 리포트·판단 반영 | 원문·근거·수정 방향을 확인하고 수용·보류·의도된 설정과 사유 저장 | P0 |
| 사건 타임라인 | 주요 사건과 시점을 카드로 정리하고 근거 원문 확인·시점 수정 | P1 |

MVP의 우선순위는 설정 충돌 검토와 작가 판단 반영입니다. 사건 타임라인은 P1으로 구분합니다. 자동 원고 집필, 이미지 인식, 실시간 공동 편집, 인물 관계도는 첫 MVP에 포함하지 않습니다.

## 사용 흐름

1. 작품의 제목·장르를 등록하고 인물·세계관 설정의 확정 여부를 지정합니다.
2. 회차 원고를 입력하고 분석에 참고할 설정과 이전 원고 범위를 선택합니다.
3. 검토 결과에서 문제 문장, 관련 근거, 판단 이유와 수정 방향을 확인합니다.
4. 결과를 수용·보류하거나 의도된 설정으로 처리하고 판단 사유를 기록합니다.
5. 원고를 수정하거나 새 회차를 검토할 때 저장된 판단을 함께 참고합니다.

## Gemini 활용

AI 분석에는 **Google Gemini API**를 사용할 예정입니다. 작품별 확정 설정, 선택한 원고, 저장된 작가 판단을 함께 참고해 검토 후보를 구성합니다.

- **관련 정보 추출:** 원고의 등장인물·행동·사건을 파악하고 비교할 설정과 이전 원고 후보를 찾습니다.
- **설정·개연성 검토:** 확정 설정과 원고를 비교해 충돌 가능성과 설명이 부족한 지점을 찾고 검토 질문을 만듭니다.
- **리포트 구성:** 문제 문장과 근거를 연결해 판단 이유와 수정 방향을 제시합니다.
- **작가 판단 반영:** 저장된 의도·예외와 적용 범위를 다음 분석의 참고 정보로 활용합니다.
- **사건 추출(P1):** 주요 사건과 시간 표현을 정리해 타임라인 초안을 만듭니다.

AI 결과는 확정 판정이 아닌 검토 후보입니다. 인물의 변화나 반전 자체를 오류로 단정하지 않고, 근거가 부족하면 판단을 유보합니다. 결과에 포함된 설정 ID와 원문 위치를 서버에서 확인하고 원고 버전과 연결하며, 설정 변경과 최종 판단은 작가가 결정하도록 설계합니다.

## 기술 구성과 개발 상태

| 영역 | 구성 |
| --- | --- |
| 프런트엔드 | React 19.2 계열, TypeScript 6.0 계열, Vite 8.3 계열, ESLint, pnpm |
| 백엔드 | Java 21, Spring Boot 4.1.1, Gradle Wrapper, Spring MVC, JPA, Bean Validation |
| 데이터베이스 | MySQL 사용 예정, 드라이버 의존성 포함 |
| AI | Google Gemini API 사용 예정 |

프런트엔드는 로그인·회원가입, 작품·설정집·회차 원고 관리, AI 검토 시연과 작가 판단 저장, 사건 타임라인을 임시 데이터로 구현했습니다. 백엔드 API와 Gemini는 연결하지 않았으며 실제 인증도 수행하지 않습니다. 실행과 시연 방법은 [프런트엔드 안내](frontend/README.md)를 참고하세요.

상세 요구사항과 일정은 [Notion 프로젝트 기획서](https://app.notion.com/p/_Magister-3eac29dbef40809b8150f5dc8e403d2e)에서 관리합니다.

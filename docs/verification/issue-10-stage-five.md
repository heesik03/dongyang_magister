# 이슈 #10 — 5단계 구현·검증 (2026-10-27)

이 문서는 5단계 완료 시점의 기록이다. 이후 수정과 현재 판정은 [1~5단계 최종 검토](issue-10-final-review.md)를 참고한다.

## 구현 결과

- `DELETE /api/work/{workId}?version={현재버전}`: 세션·CSRF·소유권과 최신 작품 버전을 검사한다. 성공 204(본문 없음), 버전 충돌 409, 타인·없는 작품 404, 잘못된 버전 400이다.
- 작품 → 작업 ID 순서로 잠그고 활성 작업을 종료시킨 뒤, 재분석 판단 참조 → 판단 범위 → 판단 이력 → 검토 근거 → 후보 → 분석 원본 → 작업 → workspace → 회차 → 설정 → 작품 순으로 한 트랜잭션에서 삭제한다. 커밋 후 로컬 실행기를 취소한다. 롤백 시 자료와 실행 상태를 보존한다. 다른 서버도 유지보수에서 사라진 작업을 감지하며 늦게 온 완료 결과는 버린다.
- 삭제 화면에서 최신 제목·버전을 확인하고 제목을 입력한다. 충돌 시 입력을 유지하고 최신 작품을 명시적으로 다시 확인한다. 서버 삭제가 확인된 뒤 해당 작품의 캐시·자동 저장 타이머·대기 mutation·복구 자료·판단 초안만 제거한다. 늦은 목록·저장 응답으로 작품을 복원하지 않는다. 다른 탭의 삭제 이벤트는 서버 404를 확인한 뒤 반영한다.
- 판단 초안은 계정·작품·검토별 `sessionStorage`에 보관한다. 명시적으로 복구하며 이전 버전·근거·작성 내용·실패한 요청 식별자를 유지한다. 최신 판단과 비교 후 기준 변경을 선택할 수 있다. 손상된 자료는 자동 덮어쓰기하지 않고, 보관 실패 시 현재 입력과 서버 저장을 유지하며 경고한다. 서버 저장 성공 시 초안을 정리한다.
- 최신 workspace 쓰기는 `separateChapters=true`, `separateReviews=true`, 빈 chapters·analyses와 events만 전송한다. 과거 검토 JSON은 서버에서 보존한다. 최초 구형 문서 가져오기 이후 판단 변경·삭제는 거절한다. 새 판단은 전용 API에만 기록하며 과거 기록에 위치·범위를 추정해 채우지 않는다.
- 정책 안내 버전 `2026-10-27.1`에 작품 삭제 경로와 외부 공급자 자료 회수 한계를 반영했다. 자동 보관 설정은 기본 0(자동 삭제 없음)이며 판단 근거 보호를 유지한다.
- 화면 검증에서 발견한 StrictMode 정리 경합을 수정했다. 이전 Provider의 비동기 정리 작업이 새로 초기화한 같은 계정 상태를 지우지 않도록 생명주기를 검사한다. autofocus 지정 입력을 닫기 버튼보다 먼저 포커스한다.
- 새 테이블·마이그레이션은 없다. 실행에 필요한 V1–V13은 유지했다. 사용자가 삭제한 기존 검증 문서 3개는 커밋에 포함하지 않는다.

## 범위를 지정한 로컬 검증

전체 테스트를 일괄 실행하지 않았다. 변경한 기능과 직접 영향을 받는 클래스·메서드·파일만 실행했다.

- 프런트엔드: `pnpm test --run tests/work-deletion.test.tsx tests/decision-flow.test.tsx tests/works.test.tsx tests/domainClients.test.ts tests/workspace-ui.test.tsx` — 55개 통과. 이후 초안 보관 실패·계정 분리·Dialog 초점 추가 변경은 관련 파일만 재검증했다. 최종 수정 기준 6개 영향 파일의 서로 다른 57개 테스트가 분할 실행으로 통과했다.
- 프런트엔드 정적 검사: `pnpm build`, `pnpm lint`, `pnpm format:check` 통과. 백엔드 패키징: `.\gradlew.bat build -x test --max-workers=2` 통과(앞서 검증한 테스트를 빌드에서 재실행하지 않음). `git diff --check` 통과.
- 백엔드: `test --tests '*WorkApiTests' --tests '*WorkspaceApiTests' --tests '*AnalysisJobLifecycleTests'` 및 새 `DecisionFlowTests` 삭제·롤백 메서드. 초기 실패는 테스트 fixture의 detached 연관관계와 CSRF 선행 응답 기대값을 수정했다. 수정한 삭제 권한 메서드와 정책 미리보기 메서드, 새 삭제·롤백·workspace 호환 메서드를 각각 좁혀 다시 검증했다. 기존 lifecycle·workspace 메서드들은 통과했다.
- MySQL 8.0.41: `mysqlTest --tests '*MySqlRefactoringTests.decisionVersionsScopesReferencesAndWorkDeletionOnMySql' --max-workers=2` 통과. 범위·장면·참조 FK, 삭제 순서, 다른 작품 보존과 늦은 결과 차단을 확인했다. 전용 `magister_refactor_51043452f552` 스키마만 사용하고 검증 후 삭제했다.
- UI: H2/8080 + 모의 Gemini로 별도 실행. 390×844 모바일에서 삭제 제목 확인·Esc 확인·초안 보관 후 재열기·복구·원래 버튼으로 포커스 복귀를 확인했다. 삭제 모달의 가로 넘침 없음. 브라우저에서 영구 삭제 버튼은 실행하지 않았으며 실제 삭제는 격리 DB 테스트에서 검증했다. 실제 사용자 작품을 조회·삭제하지 않았다.

## 실제 Gemini 평가 — 품질 통과 아님

실제 설정 모델 `gemini-3.5-flash-lite`에 고정 합성 자료 8개를 전송했다. 최초 평가와 모호한 출력 enum 예시 수정 후 재평가를 각각 1회(총 16회) 실행했다. 사용자 작품은 보내지 않았다. 원시 합성 응답과 판정은 [JSON 기록](issue-10-gemini-evaluation.json)에 보존했다. 일반 `test`와 분리한 `geminiTest`는 8회 상한·인증/호출 한도 오류 시 중단·계약 및 의미 기대 검증을 갖는다.

| 재평가 사례 | 응답 계약·위치 | 기대 의미 | 시간(ms) |
| --- | --- | --- | ---: |
| 정상 원고 | 통과 | 통과 | 2,375 |
| 설정 충돌 | 실패 | 위치 오류로 저장 거절 | 1,529 |
| 동기 설명 부족 | 통과 | 누락(빈 후보) | 1,120 |
| 명시된 반전 | 통과 | 통과 | 1,004 |
| 근거 부족 | 통과 | 통과 | 1,026 |
| 의도 범위 안 | 통과 | 통과 | 1,604 |
| 의도와 무관한 동료 충돌 | 실패 | 위치 오류로 저장 거절 | 1,798 |
| 의도 범위 밖 | 실패 | 위치 오류로 저장 거절 | 1,302 |

평균 1,470ms, 8회 합계 11,758ms(클라이언트 측 호출·검증 시간, 실제 토큰 비용 산정 아님). 정상·반전·근거 부족·의도 범위 안의 음성 4건에서는 오탐이 없었으나 표본이 작아 일반화할 수 없다. 설명 보완 양성 1건을 놓쳤다. 충돌 응답 3건은 정확한 인용 위치 계약을 위반하여 저장하지 않았다. 예를 들어 14자 원문의 전체 인용을 `[0,13)`으로 반환하고 18자 근거를 `[0,16)`으로 반환했다. 무관한 동료 충돌은 인식했지만 근거 길이가 틀렸고, 범위 밖 응답도 인용 길이와 구간이 맞지 않았다.

모호한 enum 예시를 정확한 값으로 바꾼 뒤 type 오류는 없어졌지만 위치 오류와 동기 누락이 남아 `geminiTest`는 실패했다. 위치 자동 보정·후보 누락·검증 완화로 통과시키지 않았다. **기능 구현과 로컬 회귀 검증의 완료를 실제 AI 품질 통과로 해석하지 않는다.** 긴 원고·반복 문장·혼합 언어·다양한 장르에 대한 공급자 품질 검증은 추가로 필요하다.

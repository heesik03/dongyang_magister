# 편집·연동 검증 기록

확인일: 2026-10-25. 추적 ID 추가는 요청에 따라 제외했다.

## 구현 범위

- 연관관계 최초 연결에서 contains에 의한 LAZY 컬렉션 초기화 제거, 동일 영속 ID 재호출 허용 및 소유권 이전 차단
- 설정 전체 페이지 조회와 상세 준비 상태를 분리하여 100개 이후 근거 누락·기본 선택 경합 방지
- 원고·검토 판단·사건을 작품별 서버 편집 문서로 저장: 독립 버전·중복 저장 방지·소유권·입력 검증
- 600ms 저장 디바운스, 저장 중 입력 병합, 탭 간 버전 충돌 시 입력 보존, 파일 다운로드·탭 복구본·기존 초안 명시적 가져오기
- CSRF 메모리 캐시 및 인증 경계 폐기, 전체 개수와 로드 개수 구분, 직접 URL 진입의 작품 바로가기
- 인터페이스 검증 계약·인증 문서 통일, strict 타입 검사, 설정 필터 유지와 재조회 단일화, 장르 입력 통일, 모달 ID·포커스 개선
- 비동기 AI 접수·상태·취소, 저장된 원고와 확정 설정만 전송, 반환된 설정 ID·인용문 검증, 결과와 판단 서버 저장
- 사용자별 호출 시작 간격과 공급자 전체 동시 상한 분리, 외부 호출 동안 트랜잭션 해제
- 설정 변경 시 작품 수정 시각 갱신, 민감한 메시지를 제외한 예외 종류·발생 위치 기록

## 자동 검사

- 프런트엔드: pnpm lint, pnpm build, pnpm test --maxWorkers=1, pnpm format:check
- 백엔드: .\gradlew.bat test build --max-workers=2
- 프런트 테스트 50개·백엔드 테스트 62개 통과(스킵 없음)
- 주요 회귀: 설정 101개 조회, 초기 준비 전 원고 패널 미마운트, 필터 유지·조회 횟수, CSRF 조회 재사용, 빠른 입력 저장 병합, 저장 중 추가 입력, 다른 탭의 새 버전, 저장 실패 입력 보존, 서버 문서 중복 저장·409, 소유권·CSRF·중첩 검증, 연관 컬렉션 미초기화, AI 작업 중복 방지·취소·위조 근거 거절·외부 호출의 트랜잭션 분리

## MySQL 확인

- 8080에서 패키징한 서버를 기동하여 V4~V6 마이그레이션과 스키마 검증 확인
- 작품·설정·원고·사건 저장 및 재조회, 같은 mutationId 재시도에서 버전 유지, 오래된 문서 버전의 409 응답 확인
- 임시 테이블 10,000건(작품당 100건)에 실제 설정 필터 형태로 EXPLAIN 실행: 기존 (work_id,id)는 추정 100행, 새 (work_id,kind,id)는 25행. 역방향 인덱스 탐색 유지. 실측 지연 시간의 개선 수치는 주장하지 않는다.

## 범위와 제약

- 자동 테스트의 Gemini 공급자 호출은 대역을 사용한다. 유료 외부 공급자 응답의 정확성·가용성은 별도 운영 검증 대상이다.
- 작업 실행기는 단일 서버용이며 재시작 시 미완료 작업을 실패 처리한다. 다중 인스턴스 운영에는 외부 큐·분산 호출 제한이 필요하다.
- 취소는 대기 실행/결과 공개를 막으며 이미 전송한 공급자 요청의 과금 취소를 보장하지 않는다.
- 기존 짧은 텍스트 연결 확인용 /api/gemini는 호환성을 위해 동기로 유지한다. 원고 검토 화면은 비동기 API를 사용한다.

브라우저 최종 확인: 직접 원고 URL 진입, 확정 설정 기본 선택, 외부 전송 동의 기본 해제, 원고 수정 후 서버 자동 저장과 새로고침 복원, 사건 타임라인 복원, 로그아웃을 확인했다.

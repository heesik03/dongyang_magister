# #10 1~5단계 최종 검토 (2026-10-27)

이 문서는 호출 설정 수정 전의 7/8 검토 기록이다. 남았던 오탐 수정과 최종 20/20 재검증은 [호출 설정 수정 검증](issue-10-analysis-generation-fix.md)을 참고한다. 이하 실패·Draft 판정은 당시 결과로 보존한다.

## 판정

기획서와 이슈 #10의 P0 요구사항을 API → 트랜잭션·DB → 화면 → 테스트 순서로 대조했다. 확인된 저장 경합·포커스 오류와 AI 입력 위치 계산 문제를 수정했다. 핵심 기능의 로컬 회귀 검증은 통과했지만 실제 Gemini의 명시된 반전 오탐이 남아 **병합 준비 완료로 판정하지 않는다. PR은 Draft로 공개하며 #10을 자동 종료하지 않는다.**

## 이번 검토에서 수정한 오류

1. **분석 인용 위치 실패**: 모델이 한글·UTF-16 위치를 직접 계산해 정상 후보도 저장에 실패했다. `AnalysisPromptConverter`가 원문에서 문장/긴 문장 구간을 계산해 `quote,startOffset,endOffset`를 함께 제공하도록 바꿨다. 반복 문장 위치, 줄 경계, 2,000자 상한과 surrogate 경계를 검증했다. 저장 원본·API 형식은 그대로이며 잘못된 응답을 보정하거나 일부 후보만 빼고 성공 처리하지 않는다.
2. **설명 보완 옵션의 모호한 지시**: 설명 보완만 요청해도 출력 예시는 설정 충돌 유형을 제시했다. 작업 지시·예시를 요청한 항목에 맞췄으며 성격·목표와 행동의 비교를 독립된 검토로 명시했다. 조건 종료 후의 행동을 금지 위반으로 판단하지 말라는 지침도 보완했다.
3. **늦은 판단 저장 응답이 새 초안을 삭제**: 저장 중 창을 닫고 다시 열어 새 내용을 작성하면, 이전 요청의 성공 응답이 동일 저장소 키를 삭제했다. 저장소의 pending mutationId와 성공한 요청 식별자가 일치할 때만 정리한다. 재현 테스트의 실패 → 수정 후 통과를 확인했다.
4. **근거 모달의 포커스와 선택 시점 불일치**: 포커스는 먼저 이동하고 인용 범위는 다음 animation frame에서 선택했다. Dialog가 열린 직후 onOpen에서 포커스·구간을 함께 설정하도록 고쳤다. 첫 렌더에서 정확한 구간을 선택하고 닫은 뒤 원래 근거 버튼으로 복귀한다.

## 실행한 검증

전체 프로젝트 테스트를 무조건 실행하지 않았다. 이번 요청이 1~5단계 전체 검토이므로 해당 단계의 클래스·파일을 선택하고, 수정 뒤에는 영향받은 부분만 재실행했다.

- 백엔드 56개 통과: `test --tests '*ReviewValidationTests' --tests '*ChapterApiTests' --tests '*ChapterMigrationTests' --tests '*AnalysisFlowTests' --tests '*AnalysisJobLifecycleTests' --tests '*DecisionFlowTests' --tests '*WorkspaceApiTests' --tests '*WorkApiTests' --max-workers=2`.
- 최종 프롬프트·포맷 수정 후 `test --tests '*ReviewValidationTests' build --max-workers=2` 통과. build에도 같은 필터가 적용되어 전체 test를 반복하지 않았다.
- 프런트엔드: analysis-flow, review-flow, decision-flow, decision-draft, domainClients, works, work-deletion, workspace-ui의 8개 영향 파일을 선택했다. 초기 68개 중 근거 초기 선택 테스트가 실패했고, 수정 후 관련 3개 파일의 12개가 통과했다. 초안 경합 재현 테스트 1개를 추가하고 판단 관련 2개 파일의 10개가 통과했다. 최종 수정 기준 서로 다른 **69개** 테스트를 분할 실행해 확인했다.
- `pnpm build`, `pnpm lint`, `pnpm format:check`, `git diff --check` 통과.
- `mysqlTest --max-workers=2`: MySQL 8.0.41에서 7개 통과. 임시 스키마 `magister_refactor_a96cd981e08b`만 사용했으며 검증 후 삭제했다. 접수 직렬화, FK·유일 제약, 판단·참조·삭제, 커서 계획, 구형 데이터 전환을 검증했다.
- UI는 H2/8080과 일회용 합성 자료·완료 작업으로 확인했다. 실제 공급자는 이 UI에서 호출하지 않았다. 반복된 “마법 사용” 중 두 번째 구간 `[12,17)`으로 정확히 이동했다. 근거 모달은 `[0,5)`를 즉시 선택했고 Esc 후 근거 버튼으로 복귀했다. 390×844에서도 근거 모달 가로 넘침이 없었다. 실제 사용자 원고를 수정·삭제하지 않았다.

## 실제 Gemini — 남은 차단 사항

최종 모델은 구성된 `gemini-3.5-flash-lite`다. 이번 검토에서 고정 합성 자료만 총 26회 호출했다(위치 제공 전체 8 → 출력 예시 수정 단일 1 → 작업 지시 수정 단일 1 → 전체 8 → 조건 지침 보완 후 최종 전체 8). 통과 결과만 골라 합치지 않았으며 중간 실패와 마지막 결과를 [평가 JSON](issue-10-final-gemini-evaluation.json)에 보존했다. 공급자 호출 시 인증 키·사용자 작품은 보고서에 기록하지 않는다.

`geminiTest`는 마지막 전체 실행에서 **실패**했다. 검증 완화·후보 필터링·기대값 변경으로 숨기지 않았다. 모델의 조건부 제약 해석과 오탐 억제의 추가 개선·다양한 평가 자료 검증이 끝나기 전에는 Draft를 해제하거나 MVP 품질 검증을 완료했다고 보고하지 않는다.

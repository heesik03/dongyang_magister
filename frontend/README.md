# Magister 프런트엔드

`DESIGN.md`와 [Notion 기획서](https://app.notion.com/p/_Magister-3eac29dbef40809b8150f5dc8e403d2e)를 기반으로 만든 임시 데이터 MVP입니다.

## 실행

```sh
pnpm install --frozen-lockfile
pnpm dev
```

백엔드와 MySQL을 실행한 뒤 회원가입하고 이메일로 로그인하세요. **달빛 아래의 기록 → 2화 → AI 시연 분석**에서 충돌 후보와 설명 보완 후보를 확인하고 수용·보류·의도된 설정을 저장할 수 있습니다. 분석 설정에서 참고할 확정 설정, 이전 원고, 분석 항목과 실패 시연을 선택합니다.

## 구현 화면과 저장

- 로그인·회원가입: 서버 세션 기반 인증. 비밀번호는 서버에 PBKDF2 해시로 저장합니다.
- 작품 보관함: 검색, 장르 필터, 작품 생성과 작품 탐색.
- 설정집: 인물·세계관·주요 사건·의도한 각색 등록·수정, 확정·아이디어·AI 후보 구분.
- 원고·검토: 회차 추가·편집, 글자 크기, 분석 범위, 근거·원문 이동, 작가 판단 기록.
- 타임라인: 샘플 사건, 사건 등록·수정, 시점 미상 구분과 근거 원문 이동.

인증은 서버 세션과 HttpOnly 쿠키를 사용하며, 1시간 미사용 시 만료됩니다. 인증 상태는 Zustand로 공유하고 새로고침 시 서버에서 복원합니다. 작품은 이메일별 `localStorage`에 저장됩니다. 새로고침 후 데이터가 유지됩니다. 브라우저 저장소를 지우면 임시 데이터가 사라집니다. 원고는 외부 서버나 AI로 전송되지 않습니다. 저장 실패는 화면에 표시하며 현재 입력을 메모리에 유지합니다.

AI 시연은 샘플의 두 문장과 선택한 확정 설정을 비교하는 규칙으로 동작합니다. 일반 원고의 실제 AI 분석은 구현하지 않았습니다. 이전 원고는 범위 표시용이며 샘플 규칙의 비교 대상은 확정 설정입니다. 같은 회차·문장·근거의 판단만 재분석에 유지하며, 의도된 설정이 확정 설정을 덮어쓰지 않습니다.

## 라우팅과 구조

`src/routes.tsx`의 `guestRoutes`, `protectedRoutes`, `routes` 배열에서 화면을 관리합니다. `ProtectedRoute`는 미인증 접근을 `/login`으로 보내고 로그인 후 원래 주소로 복귀합니다. `GuestRoute`는 로그인 상태의 로그인·가입 화면 접근을 처리합니다. API의 인증 여부는 Spring Security가 검사합니다.

`src/features/`에 기능별 화면·상태·타입을 두고 `src/shared/`에 공통 레이아웃과 모달, 아이콘을 둡니다. CSS 사용자 정의 속성으로 디자인 색상을 관리합니다. 외부 통신은 Axios를 사용합니다. 개발 서버는 `/api`를 `http://127.0.0.1:8080`으로 프록시합니다. 배포 시 같은 출처에서 `/api`를 백엔드로 연결하거나 `VITE_API_URL`과 서버의 허용 출처·쿠키 정책을 함께 설정해야 합니다. 배포 시 SPA 주소를 `index.html`로 연결하는 서버 설정이 필요합니다.

## 검증

```sh
pnpm lint
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

Vitest는 분석 규칙·데이터 구조와 인증 컴포넌트를 검사합니다. Playwright는 격리된 브라우저 저장소에서 보호 라우트 → 로그인 → 분석 → 판단 저장 → 타임라인을 데스크톱·모바일로 검사합니다. 이번 작업에서는 Vitest, 린트, 빌드와 실제 브라우저 핵심 조작을 확인했습니다. Playwright CLI 테스트는 별도로 실행해야 합니다.

## 추가 의존성

React Router 7.18.4는 React 19 환경에서 URL 탐색·중첩 레이아웃·Protected Route를 담당합니다. [공식 선언형 라우팅 문서](https://reactrouter.com/start/declarative/routing)를 기준으로 구현했습니다. Vitest 5, Testing Library 16, jsdom 30은 개발 전용 로직·컴포넌트 검증에, Playwright 1.64는 E2E에 사용합니다. 실제 버전은 잠금 파일을 기준으로 하며 런타임 번들에는 테스트 도구가 포함되지 않습니다. 테스트 도구의 Vite·React·Node 호환성과 브라우저 버전은 업데이트 시 함께 확인해야 합니다.

## 추가 의존성

- Axios 1.20.0: 쿠키·CSRF 헤더를 포함하는 HTTP 요청. 모든 외부 통신은 Axios를 사용합니다.
- Zustand 5.0.16: 로그인 사용자·초기 조회·오류·로그아웃 상태 공유. 비밀번호나 세션 쿠키는 저장하지 않습니다.
- Prettier 3.9.10: 코드 포맷 통일. 버전은 pnpm 잠금 파일로 관리합니다.

E2E는 실행 중인 백엔드와 MySQL이 필요하며, 실행할 때마다 `writer-...@example.com` 테스트 계정을 생성합니다.
